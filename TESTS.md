# TESTS

`npm test` runs **155 tests, 155 pass, 0 fail, 0 skipped** (node:test, no network, about 1 s). `npm run mutation` runs the suite once as a baseline and then once per check with that single check skipped; it exits non-zero if any run stays green.

| package | tests | what |
|---|---|---|
| `packages/core` | 112 | the golden vectors below, plus unit tests (JCS refusals, recorded real devnet transactions, receipt keys, grant-checker caching, period indexing) |
| `packages/seller` | 19 | the gate on the REAL `@x402/express` middleware with a mock facilitator: enforce, observe, off, 403 reasons, receipts, caching |
| `packages/agent` | 13 | local refusals before signing, ledger, extension carriage, payer-side-caps control, the copied `verify.js` guard |
| `apps/resolver` | 11 | R1 to R4, refund once, duplicate dispute, concurrent disputes, HTTP, what is stored |

## What the tests do not cover

- The live facilitators and the real chain: that is the devnet demo (`demo-runs/`, 5 clean runs, 85 signatures in `demo-runs/signatures.md`), not the unit suite.
- The mutation mechanism skips a check; it does not prove a check is *correct*, only that some test depends on it.
- Concurrency beyond two simultaneous disputes, and RPC failure paths other than retry on 429/5xx.
