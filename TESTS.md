## Mutation table

Mechanism: every check is written as `fails(name, condition)` (`packages/core/src/guard.js`); with `IUSSUM_MUTATE=name` that check never reports a violation. A mutation that leaves the suite green would be a vacuous check. **74 checks, none survived.** Mutation proves that every check that exists is load-bearing; it cannot find a check that is missing, which is how Phase 1.1 happened: the gate review found twelve missing checks and each one now has a row below.

## What the tests do not cover

- The live facilitators and the real chain: that is the devnet demo (`demo-runs/` for Phase 1, `demo-runs-1.1/` for Phase 1.1, each 5 clean runs), not the unit suite. The demo found a failure the fake chain cannot show (the RPC signature-index lag, `docs/FEEDBACK.md`).
- The mutation mechanism skips a check; it does not prove a check is *correct*, only that some test depends on it.
- Concurrency beyond two simultaneous disputes, and RPC failure paths other than retry on 429, 5xx and the index-lag error.
